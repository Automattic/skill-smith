# `.changeset/`

This directory holds pending changesets — small Markdown files that describe per-PR release-note entries. On every push to `trunk`, the release workflow consumes the files here to open the "Version Packages" PR that bumps `package.json:version`, appends to `CHANGELOG.md`, tags the commit, creates a GitHub Release, and publishes to npm.

The full policy — when a changeset is required, bump-type rules, summary conventions, the release process, and recovery procedures — lives in [`../CONTRIBUTING.md#adding-a-changeset`](../CONTRIBUTING.md#adding-a-changeset). This README is a cheat sheet, not the source of truth.

## Quick start

- `npx changeset` — interactive. Pick the package, bump type, and write a summary.
- `npx changeset --empty` — for PRs that touch release-relevant paths but warrant no release entry (see [`../CONTRIBUTING.md#adding-a-changeset`](../CONTRIBUTING.md#adding-a-changeset) for when this applies).

## Anatomy of a changeset

A regular changeset is a Markdown file with YAML front matter (package name mapped to bump type) and a body (imperative present, no PR or author references):

```md
---
"@automattic/skillsmith": minor
---

Add `--scope failed-pairs` CLI flag to control re-evaluation scope.
```

An empty changeset has no front matter and no body — just the two fences:

```md
---
---
```

The file name (e.g. `tasty-pandas-jump.md`) is generated by `npx changeset` and has no semantic meaning; you may rename it. Do not commit changes to this `README.md` itself unless you are updating the cheat sheet.
