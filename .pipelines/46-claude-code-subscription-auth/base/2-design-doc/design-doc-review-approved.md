## Summary

This revised design is complete, sound, feasible, and honestly traced. I re-verified the core feasibility claims against the live SDK and codebase: the SDK is v0.2.141 as stated; `Options.env` is `{ [envVar: string]: string | undefined }`, structurally exactly `NodeJS.ProcessEnv`, so `claudeCodeEnv(process.env)` passes to `options.env` with no cast; `query(_params: { prompt; options? }): Query` where `Query extends AsyncGenerator<SDKMessage, void>`, so the proposed `QueryFn` (return narrowed to `AsyncIterable<SDKMessage>`) accepts the real `query` by covariant return — exactly as the doc claims; the current `query()` call passes no `options.env`, so injecting it is the only behavioral delta; `tools` / `permissionMode: "bypassPermissions"` / `allowDangerouslySkipPermissions` are all valid `Options` fields; `anthropic-api.ts:8` reads `process.env.ANTHROPIC_API_KEY` directly (confirming the Req 6 hazard is real and the copy-not-mutate safeguard is correctly targeted); the codex factory and the save/restore-`process.env` env test are an exact, reusable template (`providers.test.ts:324-356`), and the test scaffolding the new test leans on (`baseParams`, `CapturedCall`, capturing-fake pattern) exists. All three prior-iteration findings are genuinely resolved, not papered over, and I found no new substantive issues.

The three prior findings are closed as follows:

- **Req 6 traceability + observable copy property.** Decision 1 now traces to Requirement 6 / acceptance criterion 6 (line 109), a dedicated "Copy-not-mutate is the safeguard for Requirement 6" paragraph (line 108) elevates the property to an owned decision, and Decision 5 adds a second, observable assertion (assertion 2, lines 138-139) that checks `process.env.ANTHROPIC_API_KEY` still holds the sentinel after `invoke()` returns — asserted inside the `try` before the `finally` restore, with an explicit "Why assertion 2 is required" rationale that names the exact in-place-`delete` failure mode the old test could not catch. This converts Req 6 from a prose claim into demonstrable, test-backed coverage.
- **Req 5 verification chain.** A dedicated "Requirement 5 (out-of-credit account) verification chain" callout (line 111) makes the transitive chain explicit (Req 1 + Req 2 absent → documented precedence selects subscription → out-of-credit account never consulted), states honestly that the offline test covers only the precondition, and defers end-to-end confirmation to credentialed/integration testing under the named "native-binary precedence is doc-derived" risk. Decision 1 explicitly hands Req 5 / AC 5 off to this callout, so there is no double-claim and no orphan.
- **AC-level tracing.** Every decision's "Traces to" line now cites the matching acceptance criteria. AC 6 (Decisions 1, 3, 5) and AC 8 (Decision 4) — the two previously missing — are now present, and the full set AC 1-9 each has a home across the decisions plus the Req 5 callout.

The denylist-vs-allowlist reasoning, the precedence analysis (scrub set is exactly the two keys), the failure-mode/observability section, the dependency list, and the risk register are all proportional to a focused bugfix and faithful to the research record. The doc stays at design altitude — it commits to assertions and decisions without devolving into an implementation plan, and correctly defers the `delete` vs `= undefined` choice, the optional companion helper test, and the changeset to later phases. Approved.
