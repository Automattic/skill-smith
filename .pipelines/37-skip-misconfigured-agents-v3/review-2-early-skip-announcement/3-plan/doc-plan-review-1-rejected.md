## Issue 1 (blocking) — The survey misses `.changeset/skip-misconfigured-agents.md`, which also says "announced once"

**What the plan claims.** doc-plan.md line 23 (CHANGELOG.md row): "Changesets-driven per
CONTRIBUTING (regenerated by `changeset version` at release). **No change** — not
hand-edited." doc-plan.md line 27-28: "the **only** documentation surface that describes
this behavior is `README.md`, in exactly two passages."

**What the repo actually contains.** A committed, **unreleased** changeset on this branch:

`.changeset/skip-misconfigured-agents.md:5`:
> Skip a misconfigured agent instead of failing the whole run. An agent whose provider
> credential is missing is removed from the run, **announced once with its id and reason**,
> and recorded in `report.json`'s new top-level `skipped` array.

Verified facts:
- This file is the v3 feature's changeset. It is **tracked and committed** (`git log`:
  `f5ccd76 Add changeset for skip-misconfigured-agents (doc-writer)`), and it is **not on
  trunk** (`git diff --name-status origin/trunk -- .changeset/` reports it as `A`). It is
  therefore an **unreleased** changeset that `changeset version` will fold into the
  published `CHANGELOG.md` at the next release — **alongside** the new Task-7
  `early-skip-announcement.md` changeset.
- Its prose uses the **identical "announced once" word** that D1/D2 correctly identify as
  the inaccuracy the early announcement introduces. After this change ships, the published
  CHANGELOG entry derived from this file will tell users the test/improver skip is
  "announced once" — the exact wording the plan is correcting two lines away in the README.
- The `changeset-format` guardrail does **not** save you here: `scripts/validate-changesets.ts`
  only checks fences / front-matter / bump / non-empty body. It does **not** validate prose
  accuracy, so the stale wording would ship silently.

**Why this is a real gap, not pedantry.** The plan's CHANGELOG row correctly states that
`CHANGELOG.md` itself is regenerated and not hand-edited — but it **conflates** the
generated `CHANGELOG.md` with the hand-written `.changeset/*.md` prose that *feeds* it.
The pending changeset files in `.changeset/` are exactly hand-edited documentation prose,
and one of them describes this behavior with the word the plan is fixing. The survey's
"only README" conclusion is falsified by `grep -rn "announced once" .` (three hits:
README.md:62, README.md:140, and .changeset/skip-misconfigured-agents.md:5 — the plan
caught two of three).

**This is fixable two ways; either is acceptable — pick one and make it explicit:**

  **(A) Defensible no-change (likely the right call), but it must be reasoned, not omitted.**
  There is a legitimate argument that an unreleased changeset is an *immutable record of
  the change that PR made* — the v3 changeset accurately describes v3 (which announced at
  end-of-run only), and the Task-7 changeset describes this refinement ("instead of only
  in the end-of-run summary"), so the merged CHANGELOG reads as a coherent history
  (feature shipped → refined). If you take this position: **add `.changeset/skip-
  misconfigured-agents.md` as an explicit row in the survey table** with a "No change"
  verdict and that rationale, and **correct the false "only README" sentence** (line 27-28)
  to "the only surface this plan edits is README; the v3 changeset's 'announced once' is a
  deliberately-preserved historical record, contextualized by the Task-7 changeset." A
  reviewer (and the doc-writer) must be able to see the surface was *considered and
  consciously left*, not overlooked.

  **(B) Correct it.** If the team prefers the published CHANGELOG to read accurately, add a
  doc task to update `.changeset/skip-misconfigured-agents.md:5` so "announced once" matches
  D1/D2's early-and-end-of-run framing. **Caution:** this edits a `.changeset/*` file, so it
  brushes against the "changeset is a CODE task, not a doc task" boundary and the phase-5
  `changeset-format` guardrail. It does **not** conflict (you are editing prose in an
  *existing* v3 changeset, not creating/altering the Task-7 release changeset, and the bump
  line stays `minor`), but the task block must say so explicitly and must not touch the
  front-matter bump.

Recommendation: **(A)**. It is the lower-risk, more conventional choice and keeps the doc
phase clear of `.changeset/*` edits. But the plan must *say* it chose (A) and *why* —
the current silent omission is the defect.
