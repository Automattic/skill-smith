# Code Summary

## What

The Code phase implemented review-4 of Skillsmith (issue #55 / PR #56) across twelve tasks in four streams, landed in the pipeline worktree and reviewed to approval:

1. **Behavior-neutral cleanup (Tasks 1–5)** — deleted the history-scanning / pure-tombstone test files (`feature-changeset.test.ts`, `testing-project-e2e-removal.test.ts`, `selection-duplicate-name-guard-removed.test.ts`, `enumerate-two-file.test.ts`), the orphaned `assets/skill-tester-workflow.png`, the dead judge-env runtime (`setUpJudgeEnv`/`tearDownJudgeEnv`, `testing-project/eval/utils/wp-cli.mjs`, the `env:start`/`env:stop` scripts, the `judgePluginSlug` alias), and the negative-assertion cohort in the core tests; relocated the one live selection test; applied byte-parity core simplifications (a shared skills-section-bounds scanner, a single scenario-id comparator, a single `=== <rel> ===` file-inlining helper); merged the overlapping enumeration tests into one shared fixture helper and reframed `enumerate-rubrics.test.ts` as `enumerate-opaque-briefs.test.ts` with a recorded keep-reason.
2. **The judge library (Tasks 6–8)** — added `src/pipeline/judge-library.ts` (`prepareJudgeLibrary`) as the standalone owner of the library mechanics, then executed the breaking core swap replacing `roles.judge.prompt` + `paths.rubrics` with `roles.judge.library` (config types/validate/normalize, `checkPaths` gate, judge-agent prompt rework, agent-loop wiring, `rubric-loader.ts` retirement, and the type-checked `examples/skillsmith.config.ts`), and migrated the bundled testing-project onto the library (`eval/judge/README.md` + `eval/judge/rubrics/`).
3. **The centralized decision rule (Task 9)** — dropped the elevenfold two-sentence opener from every `JUDGE.md`, re-pointed the rubric sentence to the `judge-library/rubrics/…` path form, merged the dropped framing sentence into the library manual, and refit the conformance test to the new template.
4. **Ship-now extras (Tasks 10–12)** — added the additive `judging: { duration, tokenUsage? }` block to per-pair `report.json`, removed the write-only `dirName` alias from the hook-visible scenario records, and reconciled the release record with three mutually consistent changeset actions.

## Why

Review-4 discharges the accumulated cleanup and the judge-verification model change for the flexible-scenarios work: it removes churn residue and dead surfaces the audit confirmed unused, replaces the two fragile judge-material channels with a single judge-scoped library that supplies grading material to the judge only (never leaking it into the testing agent), states the pass/fail decision rule once in the harness instead of eleven times in brief prose, surfaces the previously-dropped judge duration and token usage, and drops a write-only alias — all recorded truthfully in the release record so the eventual notes match what ships.

## How

The plan sequenced twelve ordered TDD tasks so every guardrail stayed green after each commit: tombstone tests were deleted before the code they pinned, the breaking type removal and the type-checked reference example migrated in one atom, and the testing-project migration followed the core swap in its own commit because config validation runs at load time, not in `defineConfig`. Grading material reaches judges through `prepareJudgeLibrary`, which resolves `roles.judge.library` against the project root, copies the whole directory per pair to `<judgeWorkspace>/judge-library/` (with a top-level collision guard), inlines the library `README.md` as the environment manual, and emits either a sorted `judge-library/<rel>` manifest (tool-capable judges) or every file body inlined (tool-less judges, e.g. `tools: []`). The judge output instruction now carries, on every run, the all-must-pass decision rule with an explicit "unless the brief states its own decision rule" override clause plus an unconditional missing-material failure duty. The removed config keys are rejected at validation time with a migration message naming `roles.judge.library`, and a configured-but-missing library fails the run at `checkPaths`. The `judging` block is written into per-pair `report.json` under a strict presence rule (present iff the judge phase ran; `tokenUsage` iff the provider reported usage; never zero-filled). The full run diff is 74 files, roughly +2508/−2338, with the judge-library module, agent-loop wiring, and judge-agent rework as the substantive additions and the tombstone/dead-code deletions as the bulk of the removals.

## Key decisions

- **`checkPaths` stays exported from `pipeline.ts`** (test-only consumer) rather than being narrowed — recorded, not public surface.
- **The testing-project bridge stays at `eval/utils/judge-wp.mjs`** and is byte-unchanged: it self-locates its project root via `import.meta.url` and wp-env keys the warm instance by the md5 of that exact `--config` path, so a per-pair copy would break it. The reviewer's relocation amendment was rejected on this ground; `judge-wp-bridge.test.ts` pins the property and passes unmodified.
- **The `rubric-loader` self-reparse fix was deliberately not applied** — the module retires wholesale in the breaking swap, so the fix is superseded rather than shipped.
- **Two writer flags were adjudicated in the writers' favor in iteration 1 and stand:** (1) the `judging` block lives in the per-pair `report.json` (its design-specified home) and does not flow into `scenario-report.ts` aggregation, honoring the design's untouched-list over its conflicting "flows through aggregation" prose; (2) the false "`dirName` remains available as an alias" clause in `nested-scenario-folders.md` was struck as a release-record consistency fix within Task 12's goal.

## Known limitations

- One rejection cycle was needed: the initial Task 12 delivery added `src/__tests__/release-changesets.test.ts`, a test that pinned the live `.changeset/` directory's count/filenames/prose — the exact tombstone pattern the revision was mandated to purge, and a guaranteed future-CI-breakage shape. Iteration 2 deleted that file (fix commit `b59e7e7`, a pure single-file deletion) with the three shipping changesets left byte-unchanged. Release-record correctness remains enforced by `scripts/validate-changesets.ts` in CI plus the synthetic-fixture `validate-changesets.test.ts`.
- Consumer-docs realignment (README's `dirName` line and the fuller judge-library prose in `examples/`/testing-project docs) is deliberately deferred to phase 5 (spec R8); the breaking changeset records the migration in the interim.
